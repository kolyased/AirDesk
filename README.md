# AirDesk

AirDesk 0.6.0 — утилита для мониторинга Windows 10 22H2 и Windows 11 x64. Она показывает температуру, нагрузку и другие доступные показатели оборудования. Управление охлаждением экспериментальное. Условия доступа к записи и испытания описаны в [документации](docs/validation.md).

## Запуск

Распакуйте Portable ZIP целиком и запустите `AirDesk.exe` или используйте установщик для текущего пользователя. Оба пакета включают .NET Runtime. Для мониторинга подходят обычные права Windows. Состояние PawnIO, права и доступ к контроллеру видны на вкладке «Диагностика». Параметр `--monitor-only` блокирует запись на весь сеанс, `--tray` скрывает главное окно при запуске. Крестик сворачивает окно в трей, пункт «Выход» завершает работу и ждёт результата возврата BIOS/EC. Полная инструкция по установке, обновлению и откату находится в [руководстве](docs/installation.md).

В обзоре есть сводные карточки CPU, GPU, RAM, дисков и текущего охлаждения. В «Настройках» можно изменить тему, порядок и видимость карточек, состав подсказки значка и режим запуска. На вкладке «Устройства» можно выбрать видеокарту для обзора, посмотреть подробности и переименовать устройства или датчики. «Диагностика» показывает исходные имена, идентификаторы, время и качество измерений, длительность и пропуски опроса. Перед сохранением отчёта можно удалить из него нужные строки. `Ctrl+1`–`Ctrl+6` переключают вкладки. Сведения сохраняются локально.

Один щелчок по значку открывает или скрывает мини-панель у панели задач, двойной открывает главное окно. Мини-панель показывает температуру, нагрузку и состояние охлаждения. Если регулировка уже включена для проверенной группы, здесь можно выбрать стандартную кривую или последний подтверждённый профиль. «Подробности» открывают главное окно на нужной вкладке. `Esc` закрывает мини-панель.

Автозапуск включается отдельно в настройках и действует для текущего пользователя Windows. Сеанс автозапуска выполняет только мониторинг. Если переносите или удаляете сборку, сначала снимите флажок автозапуска или включите его из новой папки.

## История, уведомления и настройки

В «Настройки → История и уведомления» можно включить запись на 1 час, 1 день, 7 дней или 30 дней. По умолчанию запись выключена. В зависимости от срока AirDesk берёт доступные показания каждые 10/30/60/120 секунд, объединяет непрерывные старые записи с сохранением среднего, минимума и максимума и ограничивает файл 4 МиБ и 16 000 записями. При достижении лимита реальная история может быть короче выбранного срока. Выключение записи сохраняет уже собранные данные.

На вкладке «История» выберите устройство, датчик и диапазон времени. Пропуски показаний разрывают линию. Выборку можно сохранить в CSV или JSON. Перед очисткой всей истории AirDesk предложит экспорт, а перед сбросом конфигурации — отдельную копию настроек. История и аппаратная привязка сохраняются при сбросе конфигурации. Пользовательские файлы находятся в `%LOCALAPPDATA%\AirDesk`. При повреждении основного файла AirDesk пытается загрузить последнюю рабочую резервную копию.

Пороговое правило задаётся для конкретного датчика. Можно выбрать порог выше или ниже значения, гистерезис, время удержания и минимальную паузу между уведомлениями. Отсутствие показаний прерывает отсчёт удержания. Предупреждения охлаждения и аппаратная защита действуют независимо от пользовательских правил. Автоматической отправки истории и отчётов нет.

## Управление охлаждением

Запись доступна только для определения `INTEL X99-XD4 V2.0 / BIOS 5.11 / NCT6779D / PawnIO 2.2.0 / LibreHardwareMonitor 0.9.6`, по экспериментальной паре Fan #2 `/control/1` ↔ `/fan/1`. Для остальных конфигураций доступен мониторинг. Номер канала сам по себе не подтверждает назначение разъёма.

1. Проверьте физическое подключение, режим PWM/DC и работу вентиляторов в BIOS/EC. Канал с помпой оставьте под управлением BIOS/EC. Проверьте пуск и устойчивое вращение всех вентиляторов группы на выбранном минимуме. Для хаба программа видит только один сигнал тахометра.
2. На вкладке «Охлаждение» откройте «Дополнительно» → «Калибровка разъёма» и назовите группу. Первый этап проверяет удержание оборотов на минимуме, который должен быть не ниже текущего выхода BIOS. Второй проверяет отклик на 100%. После подтверждённого возврата исходных регистров нажмите «Подтвердить назначение». Если тест не дал устойчивого изменения RPM, привязка не сохраняется.
3. Выберите профиль и нажмите «Включить управление». В активном режиме профиль меняется сразу. В ручном режиме команда ставится в очередь через 230 мс после отпускания ползунка. Отдельно отображаются расчётное значение, отправленная команда, подтверждение выхода и RPM.
4. Кнопка «Сделать профилем по умолчанию» задаёт выбор для следующего сеанса мониторинга. После запуска подтвердите прежнее подключение и включите управление вручную. При изменении хаба, разъёма, типа сигнала или состава вентиляторов повторите калибровку. «Последний подтверждённый» восстанавливает настройки, которые исполнитель ранее принял при активном управлении.

| Профиль | Точки °C → % |
|---|---|
| Тихий | 35→40, 55→50, 70→70, 80→90, 85→100 |
| Сбалансированный | 40→40, 60→65, 75→90, 85→100 |
| Производительный | 35→60, 50→75, 65→90, 80→100, 85→100 |
| Пользовательский | 2–12 точек с перетаскиванием на графике или вводом чисел. Линия показывает ограничение по минимуму и порог 85 °C |

Команда ограничена проверенным минимумом группы. Автоматические профили повышают скорость до 15 процентных пунктов в секунду и снижают её до 5 пунктов в секунду после стабилизации 4 секунды. Для обычного снижения действует гистерезис 2 °C. От 85 °C по CPU или выбранному источнику запрашивается 100% сразу. Защита действует до снижения обоих значений до 83 °C. Если один из выбранных датчиков пропал, AirDesk прекращает расчёт профиля, регистрирует попытку 100% и запрашивает возврат BIOS/EC.

## Ограничения

- Известные процессы и службы блокируют новые записи. AirDesk различает обнаружение процесса и изменение показаний самого канала, наблюдаемое вне команд AirDesk. Сторонние утилиты закрываются пользователем. После их остановки можно снова включить управление.
- При незавершённом возврате сохранённая отметка блокирует запись после перезапуска. Перед снятием блокировки перезагрузитесь и проверьте охлаждение в BIOS/EC. Подробности находятся в `%LOCALAPPDATA%/AirDesk/cooling.log`.
- Таймер и повторные попытки работают, пока процесс и драйвер отвечают. При зависшем вызове драйвера запрос возврата ждёт освобождения вызова. Принудительное завершение и внезапное отключение питания требуют аппаратных защит BIOS/EC.

## Сборка и тесты

На Windows с .NET 10 SDK откройте `AirDesk.slnx` или соберите из терминала:

```powershell
dotnet build AirDesk.slnx -c Release
dotnet run --project tests -c Release
pwsh -File scripts/Package.ps1
```

`src/AirDesk` содержит WPF-интерфейс и адаптеры Windows. `src/AirDesk.Core` содержит модели, правила охлаждения и локальное хранение. `tests` проверяет ядро. `installer` и `scripts` собирают пакеты из одного Git-коммита. Порядок выпуска описан в [docs/releasing.md](docs/releasing.md).
