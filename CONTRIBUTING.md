# Как внести вклад в AirDesk

Для разработки нужны Git и .NET 10 SDK. Для проверки WPF и установщика используйте Windows x64. Ядро можно тестировать отдельно на других ОС.

```powershell
dotnet build AirDesk.slnx -c Release
dotnet test tests -c Release --logger "trx;LogFileName=airdesk.trx"
dotnet run --project src/AirDesk -c Release -- --monitor-only
```

Создайте ветку от актуальной `main`. В PR опишите наблюдаемую проблему, условия воспроизведения, изменения и результаты проверок. Включите тесты для исправленной логики и приложите снимок, если изменился интерфейс. Используйте настройки форматирования из `.editorconfig`. Протокол пакетов и подписи находится в [порядке выпуска](docs/releasing.md).

## Изменения аппаратного управления

- Сначала воспроизведите сценарий с подставным контроллером. Покройте запрет записи, конфликт, тайм-аут, потерю датчиков, ошибку драйвера и возврат BIOS/EC. Для новых каналов нужны точная идентификация платы, BIOS, драйвера и физическая проверка разъёма.
- На реальном оборудовании подтвердите режим PWM/DC, состав хаба, источник тахометра и отдельное подключение помпы. Автоматические проверки не доказывают физический возврат оборотов. Для аппаратного теста нужен наблюдатель у машины.
- Фиксируйте версию драйвера и приложения, условия, ожидаемый и фактический результат в [протоколе проверки](docs/hardware-acceptance.md). Для PR прикладывайте обезличенные данные.

## Как передать отчёт датчиков

Откройте «Диагностика → Отчёт оборудования». В окне предпросмотра проверьте названия, идентификаторы, время и назначение датчиков. Удалите имена компьютера и пользователя, серийные номера, пути, адреса и любые необязательные идентификаторы. Сохраните отредактированный файл вне репозитория. В публичном issue оставляйте только строки, необходимые для воспроизведения. Историю, настройки, дампы и журналы из папки пользователя передавайте только после отдельной проверки содержимого.
